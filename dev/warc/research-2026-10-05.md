# WARC recompression improvements

## Recommendation

Choose gzip output independently for each WARC record. Keep the source gzip
member when it contains exactly one valid WARC record and is smaller than the
new candidates; otherwise use the smallest independently verified candidate.
Keep zlib level 9 as the default encoder. When `--ultra` is enabled, also try the
already-qualified optional Zopfli backend on records below a measured size cap.
The output remains ordinary concatenated gzip with one record per member, so
existing WARC readers and record-level random access continue to work.

Do not add libdeflate as a required dependency in this step. It has promising
results, but its upstream project supplies a C library rather than an official
Python binding, and third-party bindings need platform and version qualification
([libdeflate documentation](https://github.com/ebiggers/libdeflate#bindings-for-other-programming-languages)).
Do not change the default to Zstandard: the WARC-Zstandard format is still
proposed/experimental, even though it supports record-aligned frames and checksums
([IIPC WARC-Zstandard specification](https://iipc.github.io/warc-specifications/specifications/warc-zstd/)).

## Measurements

All candidates below were decoded and checked against the exact WARC record
bytes. Sizes count complete gzip members, including their wrappers.

| Corpus | Current zlib 9 | Best per-record gzip trial | Difference |
| --- | ---: | ---: | ---: |
| 27 Common Crawl records, 647,604 decoded bytes | 153,868 B | 144,731 B (choose source, zlib 9, Zopfli 5 or 15 per record) | 5.94% smaller |
| Same 27 records, zlib 9 vs libdeflate 12 | 153,868 B | 146,881 B | 4.54% smaller |
| 24 consecutive Common Crawl prefix members, 289,129 decoded bytes | 71,865 B | 67,566 B (Zopfli 15 for every member) | 5.98% smaller |
| Controlled two-record mixed archive | 50,286 B current rewrite | 48,517 B (keep source or zlib 9 per record) | 1,769 B recovered |

The last row is the direct evidence for per-record selection. The source members
were 29,949 B and 23,581 B; zlib 9 produced 31,718 B and 18,568 B. The current
whole-file decision rewrote both to 50,286 B. Choosing the smaller representation
for each record would keep the first source member and use the second zlib member,
for 48,517 B total. The archive remained lossless in all three versions.

For the Common Crawl corpus, source members plus zlib 9 alone equal the current
153,868 B baseline. The additional size reduction comes from stronger encoders.
Zopfli 5 took about 3.3 seconds for the 24-member prefix versus about 0.006
seconds for zlib 9 in this run; timings are single-run research measurements,
not throughput guarantees. Zopfli is intentionally a user-selected slow path;
its upstream project explicitly describes it as slow compression that emits
standard gzip/DEFLATE streams ([Zopfli](https://github.com/google/zopfli)).

The sample is small and text-heavy: 27 records came from the public
[Common Crawl CC-MAIN-2026-39 collection](https://data.commoncrawl.org/crawl-data/CC-MAIN-2026-39/).
Twenty-four are the first complete members of one file, not a random corpus.
Other Common Crawl URLs timed out during index lookup. These values justify
candidate selection and further qualification; they do not predict savings on
other crawls or binary-heavy archives.

## Proposed behavior

1. Parse and validate records exactly as today. A source member is eligible for
   reuse only if its complete decoded contents are exactly one complete record.
   Members spanning part of a record or containing multiple records are not
   candidates.
2. For every record, compare its eligible original member with a zlib-9 member.
   Pick the smallest verified result. Keep the original on an exact size tie.
   This bounds per-record size by the smallest existing candidate without
   changing the archive-level minimum-savings policy.
3. When `ultra` is true, add optional Zopfli-15 as a candidate, using the same
   pinned optional package as other codecs. Keep the best earlier candidate if
   Zopfli is unavailable, over the qualified decoded-size cap, interrupted, or
   larger. Do not make Zopfli a required install.
4. Verify each candidate by decoding it and comparing its exact bytes with the
   source record. Then retain current whole-archive framing, fingerprint,
   savings, publication, source-snapshot, index, cancellation and resource-limit
   checks. Never weaken global operation limits to pay for an optional codec.
5. Keep gzip as the only output format in this change. Do not normalize WARC
   headers, digests, HTTP payloads, CDX/CDXJ files, or revisit records.

## Further work

- Reduce repeated decoded passes by carrying a typed source fingerprint out of
  the write pass and comparing it with the independently validated candidate.
  Tie that proof to the source snapshot and staged candidate; coordinate with
  `refactor-repack-transactions` and `add-operation-resource-budgets` before
  changing validation or accounting.
- Consider bounded parallel record encoding only after a representative corpus
  shows encoding CPU is a bottleneck. Account for worker memory and scratch
  across both WARC workers and outer bulk jobs.
- Generate a new offset map/CDXJ only as a separate, explicitly requested
  operation. Unknown index schemas and offsets in non-adjacent catalogues prevent
  safe automatic rewriting today.
- Qualify Zstandard in a separate interoperability change with the actual
  archive-reader ecosystem before adding `.warc.zst` output or dictionaries.

## Reproduction data

The bounded research harness and raw per-record results are in this directory:

- [`benchmark.py`](benchmark.py)
- [`results-2026-10-05.json`](results-2026-10-05.json)
- [`commoncrawl-results-2026-10-05.json`](commoncrawl-results-2026-10-05.json)
- [`mixed-member-evidence-2026-10-05.json`](mixed-member-evidence-2026-10-05.json)

The harness caps downloaded inputs at 8 MiB and decoded samples at 32 MiB. It
uses temporary files, never writes a rewritten archive over a source, and
independently decodes every tested candidate. Encoder timing excludes worker
startup except for the zstd CLI, which includes it; Python/libdeflate/Zopfli
results are from one local macOS ARM64/Python 3.13.7 run with zlib 1.2.12.
