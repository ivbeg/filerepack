# GitHub format survey: 2026-10-04

Completed local pilot on macOS with Python 3.9.6. Twelve purposively selected repositories produced a complete inventory of **81,671 regular files**. Downloaded **149 unique blobs** (**29,674,375 bytes**, 28.30 MiB) in ten format groups. Each source URL is pinned to a commit and each download matches its Git blob ID and recorded SHA-256.

There were **170 experiments**: one primary case per input plus a deep-processing case for each of 21 ZIP/NPZ inputs. The primary cases produced **83 verified smaller outputs**, **52 byte-identical outputs**, and **14 independently unverified SVG outputs**. Across both profiles: 93 verified smaller, 59 unchanged, 18 independently unverified. All original hashes were retained. No growth or preservation mismatch was observed under the declared comparison contracts in the corrected run.

Primary verified savings: **7,737,031 bytes (26.07% of downloaded bytes)**. Deep archive cases are a separate experiment and are excluded from this total.

## Evidence gaps

- Four source-reader rejections: one non-standard JSON document and three Parquet Variant files unsupported by the installed reader. These inputs were retained byte-identically and their bytes remain in the denominator. Input inspection is limited to its declared parser checks, not complete conformance.
- Fourteen changed SVGs lack an independent renderer (`rsvg-convert` is absent). Their raw decreases contribute zero verified savings.
- Four deep ZIP cases lack an independent comparator for changed GeoPackage/TIFF members or an embedded SVG renderer. Their decreases contribute zero verified savings.
- All 16 WebP cases were retained unchanged under the size acceptance policy. This pilot establishes no useful WebP recompression gain.
- NPZ had only five distinct eligible blobs in the selected trees; its evidence base needs expansion.
- PDF comparison covers bounded page rendering and reported information. Attachments/actions/search semantics are not independently compared. Parquet comparison uses PyArrow, also used by the encoder. See the exact contracts in [README.md](README.md).

## Local resource observations

Total elapsed time across the corrected experiments: **144.71 seconds**, including process startup and independent comparisons. Maximum sampled process-tree RSS was **509,739,008 bytes** (486.13 MiB); maximum sampled per-case work-directory size was **4,521,180 bytes** (4.31 MiB). Sampling every 100 ms can miss brief peaks. These are local observations, not resource guarantees.

## Protocol correction

The first exploratory pass incorrectly set `keep_if_larger=False`, which allows growth in the historical API. It also rejected a permitted new `ARROW:schema` record. Both harness mistakes were corrected and every case was rerun on the same original bytes and frozen runtime. The first pass remains under `first-pass-*` locally for audit and is excluded from published results.
